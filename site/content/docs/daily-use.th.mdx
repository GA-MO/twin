เปิดแท็บ Code ในโฟลเดอร์ `my-twin` (หรือ `claude` ในโฟลเดอร์นั้น) แล้วคุยเป็นภาษาปกติ ไม่ต้องจำคำสั่ง ตารางนี้คือสิ่งที่ใช้บ่อย

| พิมพ์ | ได้ |
|---|---|
| มีอะไรค้าง | สรุปงานค้าง ประชุม และเรื่องที่ต้องดูวันนี้ เรียงเรื่องสำคัญไว้ก่อน |
| จำไว้ว่า … / เตือน … | โน้ตหนึ่งไฟล์ใน `notes/` ที่ขึ้นมาใน brief เมื่อถึงกำหนด |
| สรุปประชุม แล้ววางโน้ตลงไป | สิ่งที่ตัดสินใจแล้ว งานของคุณ และงานที่ต้องส่งต่อ |
| ไปแก้ X ในโปรเจกต์ Y | worker ทำใน worktree ของโปรเจกต์นั้น แล้วรายงานกลับพร้อมปุ่มอนุมัติ |
| ถึงไหนแล้ว | worker แต่ละตัวทำอะไรอยู่ และอะไรรอคุณ |
| จด feedback: … / improve | ปรับตัวตนและวิธีทำงานตามที่คุณแก้ |
| `/twin` | แผงข้างแชตที่แสดงทุกงานที่ส่งไป กดอนุมัติหรือตอบได้จากตรงนั้น |

## สรุปงาน (brief)

ทุกครั้งที่เริ่มคุยใหม่ SessionStart hook รัน `bun twin.ts brief` แล้วใส่ผลไว้ให้ agent ก่อนคุณพิมพ์คำแรก brief รวมงานที่ส่งไปทำ โน้ตและ todo ที่ถึงกำหนด ประชุมที่ใกล้ถึง งานค้างในโปรเจกต์ และคำถามที่ agent อยากถามคุณวันนี้ แล้วเรียงตามความสำคัญ

เพราะ brief มาอยู่ในบทสนทนาตั้งแต่ต้น คำถามอย่าง `มีอะไรค้าง` หรือ `วันนี้มีประชุมอะไร` จึงตอบได้ทันทีโดยไม่ต้องไปดึงข้อมูลใหม่ ถ้าอยากเห็นทุกอย่างที่ค้าง ไม่ใช่แค่เรื่องที่ brief เลือกมา ให้พิมพ์ `ขอดูทั้งหมด` agent จะใช้ `bun twin.ts todo` ซึ่งเรียงลำดับเดียวกับ brief

แต่ละแหล่งข้อมูลใน brief มาจาก collector ดูว่ามีอะไรบ้างและเปิดปิดอย่างไรใน[brief และ collector](/th/docs/concepts/brief)

## โน้ตและการเตือน

agent จดโน้ตเป็นไฟล์ละเรื่องใน `notes/` คุณไม่ต้องบอกชนิดเอง มันเลือกจากคำที่คุณใช้

| คุณพิมพ์ | ชนิดของโน้ต |
|---|---|
| จำไว้ว่า … | `fact` เรื่องที่ต้องจำ |
| ตัดสินใจแล้วว่า … | `decision` สิ่งที่ตัดสินใจไปแล้ว |
| เตือน … / ต้องทำ … | `todo` งานที่ต้องทำ ใส่วันกำหนดได้ เช่น "ภายในวันศุกร์" |
| มีไอเดีย … | `idea` ไอเดียที่ยังไม่ได้ทำ |

นอกจากนี้ยังมี `meeting` (โน้ตประชุม) `feedback` (สิ่งที่ agent ทำไม่ถูกใจ) และ `seed` แต่ละโน้ตมีสถานะ `open`, `thinking`, `started`, `done` หรือ `dropped` โน้ตที่ยังเปิดอยู่ขึ้นใน brief และ todo ที่มีวันกำหนดจะขึ้นมาเตือนเมื่อใกล้ถึง ถ้าโน้ตไหนรูปแบบผิด brief จะขึ้นเครื่องหมาย ⚠ บอกว่าไฟล์ไหน

ไอเดียมีขั้นต่อ เมื่อคุณพูดว่า `มีไอเดีย…` หรือวางลิงก์ที่มีคนแชร์มา agent จดไว้ก่อน แล้วคิดต่อแบบที่คุณจะคิด เมื่อคุณบอกว่า `สร้างโปรเจกต์จากไอเดียนี้` มันสร้างโปรเจกต์ใหม่ให้

บน Mac คุณส่งไอเดียจากมือถือได้ด้วย สร้างโน้ตใน Apple Notes ชื่อ "nok inbox" (ใช้ชื่อ agent ของคุณ) แล้วแชร์ของเข้าไป agent จะเห็นในรอบ sync ถัดไป (ต้องเปิด collector `inbox` ก่อน)

## ประชุม

วางโน้ตประชุม recap หรือ transcript แล้วพิมพ์ `สรุปประชุม` หรือบอกว่า `ประชุมเมื่อกี้…` ถ้าเปิด collector ปฏิทินไว้ agent จะจับคู่กับนัดในปฏิทินให้ ถ้ายังไม่มีเนื้อหา มันถามหนึ่งครั้ง ไม่แต่งเอง

ผลที่ได้คือโน้ตประชุมหนึ่งไฟล์ แบ่งเป็นสิ่งที่ตัดสินใจ งานของคุณ งานของคนอื่น และเรื่องที่ยังไม่ชัด จากนั้น agent จัดงานของคุณแต่ละข้อไปที่ที่ควรไป

- งานโค้ดในโปรเจกต์ที่มีอยู่ เสนอส่ง worker พร้อม brief ที่ร่างไว้แล้ว
- งานที่ไม่ใช่โค้ด จดเป็น todo พร้อมวันกำหนดถ้ารู้
- ข้อความที่ต้องส่งหาคนอื่น ร่างในน้ำเสียงของคุณ และส่งได้ไกลแค่ที่ระดับสิทธิ์ของหมวดนั้นอนุญาต
- โปรเจกต์ใหม่ที่เกิดจากประชุม ส่งต่อเป็นไอเดีย

ท้ายสรุป มันแนะนำหนึ่งอย่างว่าควรทำอะไรก่อน

## ส่งงานไปทำในโปรเจกต์

พิมพ์ เช่น `ไปแก้ปุ่ม checkout บน iOS ในโปรเจกต์ shop` agent ไม่แก้ไฟล์ในโปรเจกต์อื่นเอง มันเขียน brief สั้นๆ แล้วส่ง worker ไปทำใน worktree แยกของโปรเจกต์นั้น ระหว่างที่ worker ทำ คุณคุยเรื่องอื่นต่อได้

เมื่องานจบ agent สรุปผลให้ว่าทำอะไรไป ตรวจอะไรแล้ว และรออะไรจากคุณ แล้วถามหนึ่งเรื่องที่ต้องตัดสินใจ

| ผลของงาน | agent ถาม |
|---|---|
| ขออนุมัติ push | เข้า branch ปลายทางของโปรเจกต์ไหม |
| ถามข้อมูล | คำถามของ worker ตามคำเดิม |
| ติดขัด | ติดอะไร และแนะนำทางไป |
| เสร็จ | ship ไหม หรือปิดงาน |

ตอบด้วยคำปกติ เช่น `ok push`, `ปิดงาน` หรือตอบคำถามของ worker ไปเลย ถามความคืบหน้าด้วย `ถึงไหนแล้ว`

ต้องมีคำสั่ง `claude` ในเครื่อง และตั้งโฟลเดอร์ code (devRoot) ไว้ ไม่งั้นต้องบอก path เต็มของโปรเจกต์ ดูกลไกทั้งหมดใน[การส่งงาน](/th/docs/concepts/dispatch)

## สอนให้มันรู้ใจ

เมื่อ agent ทำไม่เหมือนคุณ พิมพ์ `จด feedback: …` หรือ `ไม่ควร…` มันจดเป็นโน้ต `feedback` หนึ่งไฟล์แล้วตอบบรรทัดเดียว ไม่แก้ตรงนั้นถ้าคุณไม่ได้สั่ง เมื่อมี feedback ครบ 5 ข้อ หรือผ่านไป 14 วัน brief จะเตือนให้พิมพ์ `improve`

เมื่อพิมพ์ `improve` agent รวบรวมหลักฐาน คือ feedback ที่เปิดอยู่ คำที่คุณแก้มันในบันทึกประจำวัน สถิติ 7 วันว่ามันถามมากไปหรือโดนแก้บ่อยแค่ไหน และงานที่คุณต้องตามแก้ จากนั้นจัดกลุ่มตามต้นเหตุ แล้วแสดงแผนว่าจะแก้อะไรที่ไหน คุณตอบ `ทำ` ครั้งเดียว มันแก้ทั้งหมด

อีกทางที่ทำให้มันรู้จักคุณมากขึ้นคือพิมพ์ `ถามฉันหน่อย` มันจะถาม 1-3 ข้อในเรื่องที่ยังรู้จักคุณน้อยที่สุด ดูว่ามันเก็บอะไรและวัดผลอย่างไรใน[ตัวตนของคุณ](/th/docs/concepts/identity)

## แถบสถานะงาน

แถบสถานะงานอยู่เหนือช่องพิมพ์ เป็น mod ที่ setup เปิดให้ repo นี้ หน้าตาและการทำงานเหมือนกันทั้งใน Claude Desktop และในเทอร์มินัล `claude` เพราะทั้งสองวาดจาก model เดียวกัน การ์ดเหมือนกัน เรียงเหมือนกัน ปุ่มเหมือนกัน

งานที่รอคุณได้การ์ดละใบ บนการ์ดบอกประเภท โปรเจกต์ และเมื่อกี่นาทีก่อน แล้วตามด้วยสิ่งที่ขอกับปุ่ม

| การ์ด | ขึ้นเมื่อ | ปุ่ม |
|---|---|---|
| **Approval** | งานเสร็จแล้วและขออนุมัติ เช่น push | **Approve push**, **Report** |
| **Question** | worker ต้องได้คำตอบก่อนทำต่อ | **Answer**, **Report** |
| **Ready to ship** | งานมี commit ที่ยังไม่ได้ push | **Ship UAT**, **Close** |
| **Needs attention** | worker หยุดกลางทาง ติดอยู่ หรือไม่มีรายงานที่อ่านได้ | **Report** |

- **Answer** ใส่ข้อความตั้งต้นในช่องพิมพ์ ให้คุณพิมพ์คำตอบต่อเอง
- **Report** กางรายงานของงานนั้นอ่านในการ์ด
- กดปุ่มไปแล้ว ปุ่มจะกลายเป็น "Sent: … Waiting for" ตามด้วยชื่อ agent เพื่อไม่ให้ส่งซ้ำ

กรอบสีรุ้งล้อมสิ่งที่รอคุณ ใต้กรอบเป็นบรรทัดสถานะที่นับงานที่เหลือ เช่น `● nok · 1 waiting on you · 1 in progress` จุดเป็นสีเขียวเมื่อมีงานกำลังทำ ถ้าไม่มีอะไรรอคุณ กรอบสีรุ้งจะล้อมแค่บรรทัดสถานะ แถบแสดงการ์ดได้สูงสุดสองใบ ที่เหลือนับรวมอยู่ในบรรทัดสถานะ

พิมพ์ `/twin` แล้วกด Enter สองครั้งเพื่อเปิดแผงด้านข้าง ในแผงเรียงตามนี้ งานที่รอคุณ งานที่รออยู่ในหน้าต่างคุยอื่น งานที่กำลังทำพร้อม subagent แต่ละตัวว่าทำอะไรอยู่ และงานที่เสร็จแล้ว การ์ดที่รออยู่ในหน้าต่างคุยอื่นบอกว่าอยู่หน้าต่างไหน แล้ว **Approve here**, **Answer here** หรือ **Take here** จะย้ายงานนั้นมาทำต่อในหน้าต่างนี้

แถบขึ้นเฉพาะตอนมีงาน ตอนที่ agent ถามคำถามแบบมีตัวเลือกค้างอยู่ แถบจะหลบไปชั่วคราว แต่ปุ่มในแผง `/twin` ยังใช้ได้ตามปกติ
