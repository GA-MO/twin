twin is an agent that works for you inside Claude Code. It knows how you work, hands code work to another agent (a worker) in a separate copy of the project, and checks that work before it comes back to you. On this page the agent is named `nok`; each owner picks their own name.

This page follows one real run. You ask for a bug fix in the sample repo `files-admin` in one sentence, then close the run when it is done. Each scene starts with the chat you see, followed by what happened behind it at the same time. Open any step to see the real text that went in and out, and why the step exists.

<WalkthroughLegend lang="en" />

The run was recorded for this page in a sample repo built from an eval fixture, so its slug starts with `eval-` and the audit does not count it as the owner's work. `site/scripts/walkthrough.ts` pulls every text from the run's files. The agent is named `nok`, local paths are shortened, and some long outputs are cut short. Nothing is added. The chat is in Thai, the owner's language, with an English gloss under each message.

Every step has a summary line you can read without opening it. Unfamiliar terms are in the [glossary](#glossary) at the end.

## Glossary

<Accordions>
<Accordion title="Mode and the autonomy table">
The mode is the file that says who you are, how you work and the rules the agent follows; every session loads it. The autonomy table in it says how far the agent may act in each category: answering a worker's question is do-then-tell, while landing client work always asks first.
</Accordion>
<Accordion title="Brief and ask">
The brief is the work order nok writes for the worker. Its line names are Thai: `อาการ` symptom, `คงไว้` must keep working, `เสร็จเมื่อ` done when. The engine splits each result the brief asks for into an ask with an id from its line: `d` done when, `s` symptom, `r` reproduce at, `k` must keep working, `c` what to match, `m` design files.
</Accordion>
<Accordion title="Engine, worker, worktree">
The engine is twin's code (`bun twin.ts ...`), not a model. The worker is another `claude -p` that does code work without a screen. A worktree is a separate copy of the repo on the worker's own branch, so its work never mixes with the files you have open.
</Accordion>
<Accordion title="Hook, skill, contract">
A hook is a command Claude Code runs on its own when something happens, such as a session starting. A skill is a guide the model opens when a task matches its description. The contract is the set of rules the engine gives the worker on every turn; the worker cannot change it.
</Accordion>
<Accordion title="Ledger, gate, independent verifier">
The ledger is the worker's own checklist, one row per ask with its evidence. The gate is the engine checking that the ledger is complete; if not, it sends one check turn back. The independent verifier is a second model that reads the evidence itself without seeing the worker's verdicts.
</Accordion>
<Accordion title="Turn, followup, slug, push gate">
A turn is one worker round from start to report. A followup is a message that sends the same worker another turn. The slug is the run's short name, used in its branch name. The push gate means the worker can push only its own branch; any other waits for your approval.
</Accordion>
</Accordions>
