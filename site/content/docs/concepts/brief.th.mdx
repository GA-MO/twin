## brief คืออะไร

brief คือสรุปสั้นๆ ที่ SessionStart hook ใส่ให้ agent ตอนเริ่มคุยทุกครั้ง agent จึงรู้ตั้งแต่วินาทีแรกว่ามีประชุมอะไร งานไหนรอคุณ และโปรเจกต์ไหนมีของค้าง

แต่ละ collector ส่ง "เรื่องที่ต้องดู" มาพร้อมคะแนน brief รวมทุกเรื่องเป็นลำดับเดียว แล้วตัดให้พอดีความยาวที่กำหนด `bun twin.ts todo` พิมพ์ทุกเรื่องในลำดับเดียวกัน brief กับ todo จึงไม่มีทางขัดกัน แต่ละหัวข้อใน brief บอกโฟลเดอร์ที่มีรายละเอียด เช่น `state/calendar/`

งานที่ส่งไปจาก session อื่นจะขึ้นใน brief พร้อมป้าย `session อื่น` ดู[งานกับ session](/th/docs/concepts/dispatch#งานกับ-session)

## collector

collector คือไฟล์หนึ่งไฟล์ใน `collectors/` ที่ดึงข้อมูลจากแหล่งหนึ่ง เขียนผลลง `state/<ชื่อ>/` และส่งเรื่องที่ต้องดูให้ brief ไม่มีที่ลงทะเบียน โฟลเดอร์คือรายการทั้งหมด

| collector | ทำอะไร | เปิดเอง | ต้องมี |
|---|---|---|---|
| `audit` | นับสัญญาณ 7 วัน ว่าถามแล้วได้ "ทำ" กี่ครั้ง ถูกแก้กี่ครั้ง ต้องตามงานกี่ครั้ง และสัดส่วนงานที่คุณไม่ต้องแตะอีก | เปิด | |
| `calendar` | ประชุมและนัด 7 วันจากแอป Calendar เตือนเมื่อใกล้ถึง | ปิด | macOS |
| `deps` | security advisory และ dependency ที่ตามหลัง major version ใน repo ที่ใช้อยู่ วันละครั้ง | ปิด | devRoot |
| `disk` | พื้นที่ดิสก์ เตือนเมื่อเหลือน้อย พร้อมสิ่งที่กินที่มากที่สุด | เปิด | Mac หรือ Linux |
| `history` | ข้อความของคุณเองที่เคยคุยกับ Claude จากแหล่งที่คุณยินยอม วันละครั้ง | เปิด | ความยินยอม |
| `inbox` | โน้ต Apple Notes ชื่อ "`<ชื่อ agent>` inbox" สำหรับส่งไอเดียจากมือถือ | ปิด | macOS |
| `journal` | บันทึกประจำวัน คือ prompt ของคุณและ commit ต่อโปรเจกต์ ดึงตามจริง ไม่ให้ model สรุป เขียนลง `journal/` | เปิด | |
| `notes` | โน้ต todo และไอเดียที่เปิดอยู่ใน `notes/` เตือนเมื่อ feedback ครบรอบ และโน้ตที่รูปแบบผิด | เปิด | |
| `onboard` | สถานะตัวตน ไฟล์ตัวตนที่อ่านไม่ได้ และคำถามที่อยากถามคุณวันนี้ | เปิด | |
| `projects` | ทุก repo ใน devRoot ได้แก่ branch ไฟล์ที่แก้ค้าง commit ที่ยังไม่ push worktree ค้าง และงานใน plan ที่ยังไม่เสร็จ | เปิด | devRoot |
| `radar` | ข่าว AI และเทคโนโลยี และ repo น่าสนใจ คัดตามสิ่งที่คุณสนใจ วันละครั้ง | ปิด | บอกว่าสนใจอะไร |
| `runs` | งานที่ส่งไปทำและสถานะ เช่น ขออนุมัติ ถามข้อมูล ติดขัด หรือเสร็จ | เปิด | |
| `trello` | การ์ด Trello ที่ยังเปิดอยู่ของคุณ | ปิด | secret `trello-key` และ `trello-token` |

brief ไม่เตือนเรื่องแหล่งข้อมูลที่คุณไม่มี collector ที่เงื่อนไขไม่ครบจะปิดอยู่เฉยๆ

`radar` เป็นตัวเดียวที่เรียก model เบื้องหลัง วันละครั้ง และเฉพาะหลังจากคุณบอกว่าสนใจอะไรแล้ว `journal` ดึงตามจริงเพื่อไม่เสียค่าอะไรและแต่งเรื่องเองไม่ได้

collector แต่ละตัวรันใน process ของตัวเอง มีเวลาจำกัด ถ้าพังหรือช้าเกิน มันโดนหยุด และผลครั้งล่าสุดที่ดียังอยู่ brief แสดงว่าตัวไหนผิดพลาด

## เปิดและปิดแหล่งข้อมูล

collector ที่ "เปิดเอง" จะทำงานเมื่อเงื่อนไขในช่อง "ต้องมี" ครบ ณ ตอนนั้น เช่น ตั้ง devRoot ทีหลัง `projects` ก็เปิดเองโดยไม่ต้องทำอะไรเพิ่ม profile เก็บเฉพาะสิ่งที่คุณเลือกเอง

```bash
bun twin.ts profile collector.calendar=on collector.trello=on
bun twin.ts profile collector.disk=off
bun twin.ts profile devRoot=$HOME/Development
bun twin.ts profile radar="frontend developer ที่สนใจ AI agent และ design system"
```

ปกติคุณไม่ต้องพิมพ์เอง บอก agent ว่า `เปิดปฏิทินให้หน่อย` ก็ได้ ตอน onboard มันเปิดตัวที่คุณใช้ให้แล้ว

secret ของ Trello คุณใส่เองในเทอร์มินัลด้วย `bun twin.ts secret trello-key` และ `bun twin.ts secret trello-token` อย่าวาง key ในแชต

collector ที่คุณเปิดแต่เงื่อนไขไม่ครบ จะแสดงว่าปิดพร้อมเหตุผล เช่น `calendar` บน Windows

## ตารางเวลา

`setup` ตั้งตารางเวลาของ OS ให้สองงาน

- **sync ทุก 10 นาที** รัน collector ที่เปิดอยู่และถึงรอบของมัน แต่ละตัวมีรอบของตัวเอง เช่น `runs` และ `notes` ทุกนาที `calendar` ทุก 10 นาที `journal` ทุก 30 นาที `disk` ทุกชั่วโมง `deps`, `history` และ `radar` วันละครั้ง ข้อมูลจากภายนอกจึงอาจช้าได้ถึง 10 นาที brief บอกว่าข้อมูลเก่าแค่ไหน
- **daily ตอน 08:30** sync ทุกตัว ปิดงานที่ merge แล้ว สำรองข้อมูล ร่าง plan ให้ todo ที่ถึงกำหนด และแจ้งเตือนสรุปเช้า ถ้าเปิด `autoClean` ไว้ มันลบ cache และของที่สร้างใหม่ได้ด้วย

`notes`, `onboard` และ `runs` รีเฟรชทุกครั้งที่สร้าง brief ด้วย สิ่งที่คุณเพิ่งจดจึงขึ้นทันที ถ้าอยากได้ข้อมูลใหม่ตอนนี้ สั่ง `bun twin.ts sync calendar` หรือบอก agent ว่า `ดึงปฏิทินใหม่`

ถ้าติดตั้งด้วย `--no-schedule` จะไม่มีสองงานนี้ brief อัปเดตตอนเปิดคุยเท่านั้น
