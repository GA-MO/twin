ตัวตนคือสิ่งที่ทำให้ agent ตัดสินใจแบบคุณ มันไม่ใช่โค้ด และไม่ได้แชร์กับใคร ทั้งหมดเป็นไฟล์ใน `profile/` บนเครื่องคุณ เปิดอ่านและแก้ได้ ทุกครั้งที่เริ่มคุยใหม่ SessionStart hook พิมพ์ตัวตนทั้งหมดใส่ session ให้ worker ที่ส่งไปทำงานก็ได้ตัวตนนี้ด้วย

## รู้จักคุณ 6 ด้าน

การตัดสินใจเป็นแค่หนึ่งในหกด้าน

| ด้าน | ครอบคลุม |
|---|---|
| ตัวตน | บทบาท ทีม องค์กร วันปกติของคุณ ภาษาที่ใช้ |
| เครื่องมือ | เครื่องและ OS อีเมล ปฏิทิน แชต เอกสาร AI ที่ใช้ |
| งาน | ชนิดงาน โปรเจกต์ ลูกค้า งานประจำ คนที่ทำงานด้วย |
| นอกงาน | สิ่งที่กำลังเรียน งานอดิเรก สิ่งที่อ่านหรือติดตาม (ใช้คัดข่าวให้ radar) |
| ทำงานกับคุณ | อยากให้สอนทีละขั้นหรือทำให้เลย ละเอียดแค่ไหน น้ำเสียง เมื่อไหร่ควรถาม |
| การตัดสินใจ | เส้นห้าม เกณฑ์ที่ใช้ตัดสิน และ agent ทำแทนได้แค่ไหนในแต่ละหมวด |

agent จดใน `profile/coverage.md` ว่ารู้จักคุณแต่ละเรื่องแค่ไหน 0 คือยังไม่รู้ 1 คือเดา 2 คือคุณบอกเอง 3 คือคุณบอกและหลักฐานตรงกัน พร้อมหลักฐานที่มีและวันที่ถามครั้งล่าสุด มันจึงรู้ว่าเรื่องไหนยังรู้จักคุณน้อย

## onboard เรียนรู้คุณอย่างไร

`onboard` แตะทุกด้านแบบเบาๆ ในวันแรก แล้วค่อยลึกขึ้นในวันต่อๆ ไป ก่อนอื่นมันถามว่าอ่านประวัติจากที่ไหนได้บ้าง คือ transcript ของ Claude Code, ไฟล์ `conversations.json` ที่ export จาก claude.ai และ commit ของคุณ ตอบไม่ก็ได้ ถ้าถอนความยินยอมทีหลัง ข้อมูลที่เก็บไว้จะถูกลบ

ทางที่มันใช้ขึ้นอยู่กับว่ามีประวัติมากแค่ไหน

<Tabs items={['มีประวัติเยอะ', 'มีประวัติน้อย']}>
  <Tab value="มีประวัติเยอะ">
    มันขุดกฎจากประวัติก่อน แล้วให้คุณยืนยันทีละข้อพร้อมคำพูดเดิมที่เป็นหลักฐาน คุณตอบว่า ถูก ผิด หรือ "แล้วแต่ ___" ซึ่งจะได้คำถามต่ออีกหนึ่งข้อว่าแล้วแต่อะไร
  </Tab>
  <Tab value="มีประวัติน้อย">
    มันถามเป็นสถานการณ์จริง ทีละข้อ มีตัวเลือก ชุดละ 5 ข้อ หยุดได้ทุกเมื่อ ทุกคำตอบถูกจดลง `profile/interview.md` ก่อนถามข้อถัดไป ปิดหน้าต่างไปแล้ววันหลังก็ตอบต่อจากข้อเดิมได้
  </Tab>
</Tabs>

ไม่ว่าทางไหน มันใช้วิธีถามแบบเดียวกัน

- ถามถึงครั้งล่าสุดที่เกิดขึ้นจริง ไม่ถามว่า "ปกติคุณทำยังไง" เพราะคนมักเล่าตัวเองต่างจากที่ทำจริง
- คำตอบที่ตัดสินอะไรบางอย่าง ถามต่อว่าทำไมอีกสองสามชั้น
- ถามเส้นห้ามตรงๆ ว่าอะไรที่ห้ามทำในนามคุณเด็ดขาด แม้คุณไม่อยู่
- หาเกณฑ์ด้วยสถานการณ์คู่ที่เปลี่ยนทีละอย่างจนคำตอบพลิก เช่น ลูกน้องขอซื้อ tool 5,000 บาท แล้ว 15,000 แล้ว 40,000 จุดที่คำตอบพลิกคือกฎ
- ถ้าคำตอบขัดกับประวัติ มันถามพร้อมหลักฐาน ประวัติไม่ได้ชนะเสมอไป

หลัง onboard ทุกวัน brief จะเสนอ 1-3 เรื่องจากด้านที่รู้จักคุณน้อยที่สุด พิมพ์ `ถามฉันหน่อย` เมื่อสะดวก

## กฎ เส้นห้าม และระดับสิทธิ์

ตัวตนเก็บเป็นไฟล์ที่มีรูปแบบชัดเจน ทุกกฎ ทุกเส้น และทุกระดับระบุที่มา ว่ามาจากคำตอบข้อไหน หรือจากประวัติวันไหนพร้อมคำพูด

| ไฟล์ | เก็บอะไร |
|---|---|
| `profile/mode/SKILL.md` | คุณเป็นใคร เขียนเป็นร้อยแก้วสั้นๆ ทีละด้าน และหัวข้อ "ยังไม่รู้" สำหรับคำถามที่ค้าง |
| `profile/rules.json` | กฎแต่ละข้อ พร้อมเหตุผล ที่มา และว่าเป็นสิ่งที่คุณบอก (`stated`) หรือเห็นในประวัติแล้วคุณยืนยัน (`observed`) |
| `profile/red-lines.json` | สิ่งที่ห้ามทำเด็ดขาด พร้อมเหตุผลและที่มา |
| `profile/autonomy.json` | หมวดการตัดสินใจของคุณ แต่ละหมวดมีระดับ เกณฑ์ เพดาน และช่องนับการเดา |
| `profile/coverage.md` | รู้จักคุณแต่ละเรื่องแค่ไหน |

ระดับสิทธิ์มีห้าขั้น

| ระดับ | ความหมาย |
|---|---|
| `observe` ดูเงียบ | ดูและจดไว้ ยังไม่เสนออะไร |
| `ask` ถามก่อน | ถามคุณทุกครั้งก่อนทำ |
| `draft` ร่างให้ | เตรียมไว้ให้เสร็จ คุณแค่กดส่ง |
| `tell` ทำแล้วบอก | ทำเลย แล้วสรุปให้รู้ว่าทำอะไรไป |
| `silent` ทำเงียบ | ทำเองโดยไม่ต้องรายงาน |

ทุกหมวดเริ่มที่ `ask` เว้นแต่ประวัติที่คุณให้อ่านแสดงว่าคุณปล่อยเรื่องนั้นให้คนอื่นทำอยู่แล้ว สิทธิ์ให้ทีละหมวด ไม่เคยให้ทีเดียวทั้งหมด ระดับขึ้นได้เฉพาะเมื่อคุณบอก และลดลงหนึ่งขั้นหลังพลาดหนักในหมวดนั้น เส้นห้ามชนะทุกระดับ

<Callout type="info">
  ไฟล์สิทธิ์มีช่องนับการเดาไว้แล้ว ระยะถัดไป agent จะเดาก่อนว่าคุณจะตัดสินใจอย่างไร นับว่าเดาถูกกี่ครั้ง แล้วเสนอขยับระดับให้คุณยืนยัน ส่วนนี้ยังไม่ได้เปิดใช้
</Callout>

ตรวจไฟล์ตัวตนได้ด้วย `bun twin.ts identity` มันพิมพ์สิ่งที่ทุก session จะเห็น และปฏิเสธไฟล์ที่อ่านไม่ได้พร้อมบอกปัญหา

ไฟล์ตัวตนแก้โดย `onboard` และ `improve` เท่านั้น ถ้าอยากเปลี่ยนอะไร บอก agent ว่า `จด feedback: …` หรือบอกตรงๆ ว่าตรงไหนไม่ใช่

## ดีขึ้นตามเวลา

`improve` ใช้หลักฐานจริงแทนความรู้สึก มันรวม feedback ที่จดไว้ คำที่คุณแก้มันในบันทึกประจำวัน สถิติ 7 วันจาก audit และงานที่คุณต้องตามแก้ จัดกลุ่มตามต้นเหตุ แล้วแก้ที่จุดเดียวที่ตรงกับต้นเหตุนั้น เรื่องว่าคุณเป็นใครไปที่ `SKILL.md` กฎการตัดสินใจไปที่ `rules.json` สิ่งที่ห้ามทำไปที่ `red-lines.json` ข้อมูลผิดหรือ brief รกไปที่ collector

ตัวเลขหลักที่บอกว่ามันดีขึ้นหรือไม่ คือ **สัดส่วนงานที่ส่งไปแล้วคุณไม่ต้องแตะอีกเลย** หมายถึงงานที่ไม่มีข้อความตามจากคุณ นอกจากการอนุมัติหรือการตรวจที่ engine ขอเอง audit นับงานหนึ่งเมื่อปิดแล้ว หรือผ่านไป 12 ชั่วโมงหลัง turn สุดท้าย งานที่ใหม่กว่านั้นยังไม่นับ ตัวเลขนี้นับจากไฟล์งานจริง ไม่ได้ให้ model ตัดสิน audit แสดงทุกสัปดาห์เทียบกับสัปดาห์ก่อน และเทียบช่วงก่อนกับหลัง improve ครั้งล่าสุด

eval ไม่ใช่ตัวเลขนี้ มันเป็นราวกั้นไม่ให้ improve ทำของพัง ทุก commit ที่ขึ้นต้นด้วย `improve:` ต้องผ่าน `bun twin.ts eval` ชั้นเร็วก่อน ใช้เวลาราวหนึ่งนาที และกันเฉพาะสิ่งที่ตรวจได้แน่นอน เช่น ไฟล์ตัวตนอ่านไม่ได้ หรือ test พัง ถ้าอยากวัดเต็มรูปแบบ สั่ง `bun twin.ts eval full` ซึ่งใช้เวลาหลายสิบนาที รายละเอียดอยู่ใน[เหตุผลของการออกแบบ](/th/docs/design#วัดจริง-ไม่เดา)
