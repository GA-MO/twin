agent ตัดสินใจจากสิ่งที่อยู่ใน context window ตอนที่มันตัดสินใจ ไม่ได้ตัดสินจากสิ่งที่อยู่ใน `profile/` กฎที่ไม่เคยเข้าไปถึง context ไม่มีผลอะไรเลย ต่อให้เขียนไว้ดีแค่ไหน หน้านี้อธิบายว่า twin พาตัวตนเข้าไปในทุก session และรักษาไว้อย่างไร ข้อจำกัดอะไรใน Claude Code ที่กำหนดวิธีนี้ และมีความเสี่ยงอะไรที่ยังเหลืออยู่

## สี่ช่องทาง

twin ส่งข้อความเข้า session ของ Claude Code ผ่านสี่ช่องทาง แต่ละช่องมีอายุและข้อจำกัดของตัวเอง

| ช่องทาง | ใส่อะไร | อยู่นานแค่ไหน | ข้อจำกัด |
|---|---|---|---|
| CLAUDE.md import | mode กฎ เส้นห้าม ระดับการทำแทน (`state/mode.md`) | ตลอด และอยู่หลัง compaction | 40,000 ตัวอักษร งบที่ twin ตั้งเอง |
| SessionStart hook | brief ข้อความเตือนสั้นๆ | turn แรก และทำงานใหม่ตอน compaction | ราว 10,000 ตัวอักษร |
| skill | `dispatch`, `improve`, poteto-mode | เมื่อถูกเรียก และหายตอน compaction | ไม่มี |
| โค้ด | guard hook, push gate, eval gate | ไม่อยู่ใน context แต่บังคับตลอด | ไม่มี |

ตัวตนอยู่ในช่องแรก เพราะเป็นช่องเดียวที่อยู่ตลอดและรอดจาก compaction กฎที่พลาดไม่ได้อยู่ในช่องที่สี่ เพราะโค้ดไม่มีวันลืม hook ใช้ส่งสิ่งที่เปลี่ยนไปในแต่ละ session ส่วน skill ใช้เก็บวิธีทำงานยาวๆ ที่งานบางอย่างเท่านั้นต้องใช้

## สิ่งที่วัดได้

วัดบน Claude Code 2.1.312 เมื่อ 2026-10-30 แต่ละการทดสอบเป็น session `claude -p` ใหม่ที่ตอบจาก context ของตัวเองโดยไม่ใช้ tool

- **output ของ hook มีเพดาน** hook ที่พิมพ์ 9,000 ตัวอักษรเข้าไปครบ ส่วนที่พิมพ์ 10,500 ตัวอักษรถูกเก็บลงไฟล์ และ session ได้แค่ตัวอย่าง 2 KB
- **CLAUDE.md ถูกอ่านก่อน hook ทำงาน** hook เขียนไฟล์ที่ CLAUDE.md import ใหม่ session นั้นยังเห็นเนื้อหาเก่า session ถัดไปจึงเห็นของใหม่
- **ไฟล์เดียวกันถูก import สองทาง โหลดครั้งเดียว** `CLAUDE.md` ของ repo นี้และ `~/.claude/CLAUDE.md` import `state/mode.md` ทั้งคู่ session ใน repo นี้มีแค่ชุดเดียว
- **CLAUDE.md รอดจาก compaction** หลัง `/compact` session ยังยก bullet สุดท้ายของ mode มาได้ตรงทุกคำ
- **import ไฟล์ที่ไม่มีอยู่ ถูกข้ามเงียบๆ** ไม่มีอะไรใน session บอกว่าหาไฟล์ไม่เจอ
- **path ของ import มีกติกา** path นับจากไฟล์ที่ import ช่องว่างต้องเขียนเป็น `\ ` และใน session `claude -p` `CLAUDE.md` ของ project ไม่โหลด path เต็มที่อยู่นอก project แต่ `~/.claude/CLAUDE.md` โหลด
- **`--setting-sources project,local` ตัด `~/.claude/CLAUDE.md` ออก** run แบบ isolated จึงต้องได้ mode ทางอื่น
- **skill ไม่รอดจาก compaction** เรียก skill ขนาด 18 KB และอ่านครบแล้ว หลัง `/compact` session เห็นมันแค่ในฐานะที่ถูกพูดถึงในสรุป วัดไว้หนึ่ง skill และ twin ถือว่าทุก skill เป็นแบบเดียวกัน

## ปัญหาที่ทำให้ออกแบบแบบนี้

ก่อนวันที่ 2026-10-30 SessionStart hook พิมพ์ mode ทั้งหมด ซึ่งโตจนถึง 31,042 ตัวอักษร Claude Code เก็บมันลงไฟล์แล้วส่งต่อแค่ตัวอย่าง 2 KB ใน 73 จาก 80 session ล่าสุด คือทุก session ตั้งแต่ 2026-10-22 agent ทำงานโดยมี mode แค่ย่อหน้าแรก ไม่มีเส้นห้าม ไม่มีตารางระดับการทำแทน ไม่มีกฎ และไม่มี session ไหนเปิดไฟล์ที่ถูกเก็บไว้ขึ้นมาอ่าน เพราะตัวอย่างขึ้นต้นว่า "loaded in full"

eval gate จับไม่ได้ เพราะ replay รัน session ผ่าน hook ตัวเดียวกัน จึงวัดตัวตนที่ถูกตัดแบบเดียวกันทั้งก่อนและหลัง improve ทุกครั้ง improve ที่แก้ร้อยแก้วใน mode จึงไม่เปลี่ยนอะไรที่ session มองเห็น บทเรียนบางข้อยังได้ผลอยู่ เพราะมันอยู่นอก hook คือใน `CLAUDE.md` ของ repo, auto-memory ของ Claude Code, โค้ดของ engine และสัญญาของ worker

บทเรียนสำหรับทุกอย่างที่โหลด context คือให้ทดสอบสิ่งที่ไปถึง ไม่ใช่สิ่งที่ส่งไป ให้ session ใหม่ยกบรรทัดสุดท้ายของไฟล์มาให้ดู ไม่ใช่บรรทัดแรก

## twin รักษาตัวตนให้ครบอย่างไร

- **ไฟล์เดียวที่ render แล้ว** `state/mode.md` มีร้อยแก้วของ mode ตามด้วยเส้นห้าม ตารางระดับการทำแทน และกฎ `bun twin.ts identity` กับ `setup` เป็นตัวเขียน และ mode hook เขียนใหม่ทุกครั้งที่ `startup`, `resume`, `clear` และ `compact`
- **import สองที่** `CLAUDE.md` ของ repo นี้ import ไฟล์นี้ ถ้าใช้ scope แบบ global ซึ่งเป็นค่าเริ่มต้น `~/.claude/CLAUDE.md` ก็ import ด้วย session ในโฟลเดอร์อื่นและ worker ที่ส่งไปทำงานจึงได้ตัวตนด้วย `setup --scope project` จะเอาบรรทัด import ออกจาก `~/.claude/CLAUDE.md` จึงมีแค่ session ใน repo นี้ที่โหลด mode
- **เตือนเมื่อจำเป็นเท่านั้น** CLAUDE.md ถูกอ่านก่อน hook ทำงาน ดังนั้นเมื่อ hook พบว่า mode เปลี่ยน หรือเพิ่งต้องเพิ่มบรรทัด import มันจะบอก session ให้อ่าน `state/mode.md` ทันที ถ้าไม่มีอะไรเปลี่ยนและไม่ได้ compact จะไม่พิมพ์อะไรเลย
- **เตือนหลัง compaction** ตอน `compact` hook บอก session ให้เรียก skill ที่งานปัจจุบันยังต้องใช้ใหม่ทุกตัว
- **งบขนาด** twin คุม mode ที่ render แล้วไว้ไม่เกิน 40,000 ตัวอักษร เป็นงบที่ตั้งเอง `bun twin.ts identity` บอกขนาดและจบด้วย code 1 เมื่อเกิน และ eval gate กัน commit `improve:` ที่เกิน
- **ตรวจสิ่งที่ไปถึงทุกวัน** collector `identity` เปิด session `claude -p` ใหม่วันละครั้ง นอก repo นี้เมื่อใช้ scope global ส่งคำแรกๆ ของบรรทัดสุดท้ายใน mode ไปแล้วให้ยกทั้งบรรทัดมา โดยปิด tool และ MCP server ทั้งหมด ถ้ายกไม่ได้จะขึ้นเตือนใน brief พร้อมเวอร์ชันของ Claude Code การอัปเดตที่ตัดตัวตนจึงเห็นภายในหนึ่งวัน ผลอยู่ที่ `state/identity/index.md`
- **run แบบ isolated** replay รันใน repo นี้ จึงได้ import ไปด้วย ส่วน worker แบบ isolated ใน repo อื่นได้ mode ต่อท้ายสัญญาเมื่อ scope เป็น global เหมือนที่ worker จริงได้จาก `~/.claude/CLAUDE.md`

## ความเสี่ยงที่ยังเหลือ

การโหลดตัวตนให้ครบเป็นสิ่งจำเป็น แต่ยังไม่พอ ความเสี่ยงเหล่านี้ยังอยู่ และนี่คือสิ่งที่ twin ทำกับแต่ละข้อ

| ความเสี่ยง | เกิดอะไรขึ้น | อะไรช่วยจำกัด |
|---|---|---|
| ความสนใจเจือจางใน session ยาว | กฎยังอยู่ แต่มีน้ำหนักน้อยลงเมื่อ context เต็มไปด้วย output ของ tool ที่อยู่ห่างจากกฎ | session สั้น หนึ่ง session หนึ่งงาน งานยาวส่งให้ worker ที่ context สะอาด compaction เก็บ mode ไว้แล้วทิ้งส่วนที่เหลือ |
| agent ลอกตัวเอง | คำตอบก่อนหน้าที่เลี่ยงกฎ กลายเป็นตัวอย่างให้คำตอบถัดไป | คำที่เจ้าของแก้ถูกจดเป็น feedback และ `improve` เปลี่ยนเป็นกฎ |
| ตัวตนบวม | improve แต่ละครั้งเพิ่มข้อความจนไฟล์เจือจางตัวเอง | เพดาน 40,000 ตัวอักษร และ improve เขียนกฎเดิมใหม่เมื่อกฎใหม่แคบลง แทนที่จะเพิ่มข้อที่สอง |
| โมเดลรุ่นใหม่อ่านต่างไป | ข้อความเดิมแต่พฤติกรรมเปลี่ยน | gate แบบเร็วทุกครั้งที่ improve และ `eval full` เมื่อคุณสั่ง |
| ไม่เรียก skill กลับมา | หลัง compaction agent อาจทำต่อโดยไม่มีวิธีทำงานที่ใช้อยู่ | ข้อความเตือนตอน compact แต่ยังไม่ได้วัดว่า agent ทำตามจริงไหม |
| สอง session เริ่มพร้อมกัน | ทั้งคู่โหลดไฟล์เก่า hook ตัวแรกเขียนไฟล์ใหม่และเตือน session ของมัน hook ตัวที่สองเห็นว่าไม่มีอะไรเปลี่ยน session นั้นจึงใช้ mode เก่าโดยไม่มีข้อความเตือน | เกิดได้แค่หนึ่ง session หลังแก้ไฟล์โดยไม่ได้รัน `bun twin.ts identity` |

กฎที่พลาดไม่ได้ไม่ได้พึ่ง context เลย guard hook ห้ามเขียนใน `state/` และใน repo อื่น push gate ปฏิเสธทุก ref ยกเว้น branch ของ worker เอง และ eval gate กัน improve ที่ทำให้การตรวจที่รันได้พัง

## ตรวจเอง

```bash
bun twin.ts identity
```

คำสั่งนี้พิมพ์เส้นห้าม ตารางระดับการทำแทน และกฎ แล้วบอกขนาดที่ทุก session โหลด เช่น `ทุก session โหลด 26,572 / 40,000 ตัวอักษร` ถ้ามีไฟล์ที่อ่านไม่ได้หรือ mode ยาวเกิน มันจะจบด้วย code 1

ถ้าจะดูว่า session ได้รับอะไรจริง ให้เปิด session ใหม่ในโฟลเดอร์ที่อยู่นอก repo นี้ แล้วให้มันยกกฎข้อสุดท้ายใน mode และเส้นห้ามมาหนึ่งข้อโดยไม่ใช้ tool ถ้ามันทำไม่ได้ แปลว่าบรรทัด import ใน `~/.claude/CLAUDE.md` หายไปหรือเสีย session ถัดไปใน scope global จะใส่กลับให้เอง หรือรัน `bun twin.ts setup` ก็ได้ ถ้าใช้ `--scope project` ให้ตรวจใน repo นี้แทน
