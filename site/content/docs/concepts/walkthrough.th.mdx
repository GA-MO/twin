twin คือ agent ที่ทำงานแทนคุณใน Claude Code มันรู้จักวิธีทำงานของคุณ และส่งงานโค้ดไปให้ agent อีกตัว (worker) ทำในสำเนาแยกของ project แล้วตรวจงานก่อนส่งกลับมาหาคุณ ในหน้านี้ agent ชื่อ `nok` เจ้าของแต่ละคนตั้งชื่อเองได้

หน้านี้เล่า run จริงหนึ่งรอบ คุณสั่งแก้บั๊กใน repo ตัวอย่าง `files-admin` ด้วยประโยคเดียว แล้วปิดงานเมื่อเสร็จ ทุกฉากเริ่มจากแชทที่คุณเห็น แล้วตามด้วยสิ่งที่เกิดเบื้องหลังในช่วงเวลาเดียวกัน กดที่ขั้นไหนก็ได้เพื่อดูข้อความจริงที่เข้าและออก และเหตุผลของขั้นนั้น

<WalkthroughLegend lang="th" />

run นี้บันทึกจริงเพื่อหน้านี้ ใน repo ตัวอย่างที่สร้างจาก fixture ของ eval slug จึงขึ้นต้นด้วย `eval-` ซึ่งทำให้ audit ไม่นับ run นี้เป็นงานของเจ้าของ ข้อความดึงจากไฟล์ของ run ด้วย `site/scripts/walkthrough.ts` ชื่อ agent ใช้ `nok` path ในเครื่องถูกย่อ และข้อความยาวบางช่วงถูกตัดให้สั้น ไม่มีการแต่งเพิ่ม

ทุกขั้นมีบรรทัดสรุปให้อ่านได้เลย คำที่ไม่คุ้นอยู่ใน [ศัพท์](#ศัพท์) ท้ายหน้า

## ศัพท์

<Accordions>
<Accordion title="mode และตาราง ระดับการทำแทน">
mode คือไฟล์ที่บอกว่าคุณเป็นใคร ทำงานอย่างไร และกฎที่ agent ต้องทำตาม ถูกโหลดทุก session ตารางระดับการทำแทนอยู่ใน mode บอกว่าเรื่องแต่ละหมวด agent ทำเองได้แค่ไหน เช่น ตอบคำถามของ worker ให้ทำแล้วบอก ส่วนลงงานลูกค้าต้องถามก่อนทุกครั้ง
</Accordion>
<Accordion title="brief และ ask">
brief คือใบสั่งงานที่ nok เขียนให้ worker แต่ละบรรทัดมีชื่อภาษาไทย เช่น `อาการ` `คงไว้` `เสร็จเมื่อ` engine แตกผลที่ brief ขอเป็นข้อ (ask) แต่ละข้อได้ id ตามบรรทัดที่มา: `d` เสร็จเมื่อ, `s` อาการ, `r` ทำซ้ำที่, `k` คงไว้, `c` ต้นแบบ, `m` ไฟล์แบบ
</Accordion>
<Accordion title="engine, worker, worktree">
engine คือโค้ดของ twin (`bun twin.ts ...`) ไม่ใช่ model worker คือ `claude -p` อีกตัวที่ทำงานโค้ดโดยไม่มีหน้าจอ worktree คือสำเนาแยกของ repo บน branch ของ worker เอง งานของ worker จึงไม่ปนกับไฟล์ที่คุณเปิดอยู่
</Accordion>
<Accordion title="hook, skill, contract">
hook คือคำสั่งที่ Claude Code รันเองเมื่อเกิดเหตุการณ์ เช่นเปิด session skill คือคู่มือที่ model เปิดอ่านเมื่องานตรงกับคำอธิบายของมัน contract คือกติกาที่ engine แนบให้ worker ทุกรอบ worker แก้ไม่ได้
</Accordion>
<Accordion title="ledger, gate, ผู้ตรวจอิสระ">
ledger คือรายการตรวจของ worker เอง แถวละหนึ่ง ask พร้อมหลักฐาน gate คือ engine เช็คว่า ledger ครบ ถ้าขาดจะส่ง turn ตรวจกลับไปหนึ่งรอบ ผู้ตรวจอิสระคือ model อีกตัวที่อ่านหลักฐานเองโดยไม่เห็นคำตัดสินของ worker
</Accordion>
<Accordion title="turn, followup, slug, push gate">
turn คือ worker หนึ่งรอบตั้งแต่เริ่มจนรายงาน followup คือข้อความที่ส่งต่อให้ worker ตัวเดิมทำรอบถัดไป slug คือชื่อสั้นของงานที่ใช้ตั้งชื่อ branch push gate คือ worker push ได้แค่ branch ของตัวเอง branch อื่นต้องรอคุณอนุมัติ
</Accordion>
</Accordions>
