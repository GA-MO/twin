# Audit ที่เรียนรู้เองได้ และปิดจุดอ่อนของ twin

ที่มา: เจ้าของถามว่า twin ใช้งานได้จริงแค่ไหน และสั่งให้ปิดจุดอ่อนทุกด้าน โดยเอาเฉพาะที่ทำแล้วดีขึ้น (12 พ.ย. 2026)

ขนาด: กลาง ต่อ phase (แก้หลายไฟล์ใน engine) · จบ phase ละหนึ่ง commit · ตรวจ diff สุดท้ายของแต่ละ session ด้วย reviewer อิสระหนึ่งตัว · session ละ 1 ถึง 2 phase

## ตัดสินไว้แล้ว

- ตัวเลขทุกตัวนับจากไฟล์ ไม่เรียก model เบื้องหลัง (ตาม design: no background model calls)
- audit ไม่ถอยหรือแก้อะไรเอง มันบอกคำตัดสิน เจ้าของสั่งผ่าน `improve`
- คำตัดสิน "ดีขึ้น" หรือ "แย่ลง" ออกได้เมื่อส่วนต่างเกิน 2 เท่าของความแกว่งที่เกิดเองได้เท่านั้น นอกนั้นบอกว่า "แยกไม่ออก"
- ระดับการทำแทนขยับเมื่อเจ้าของสั่งเท่านั้น

## Phase 1: ประวัติไม่หาย และเตือนเมื่ออ่านไม่ได้

สถานะ: เสร็จ 12 พ.ย. 2026 (commit เดียวกับ Phase 2) ผลวัดอยู่ใน docs/design.md หัวข้อ Changes since

ปัญหา: Claude Code ลบประวัติ session ตาม `cleanupPeriodDays` (14 วันบนเครื่องที่สร้าง) ยอดสะสมจึงหดทุกวัน และถ้ารูปแบบไฟล์ประวัติเปลี่ยน ตัวเลขจะเป็นศูนย์โดยไม่มีใครรู้

- `lib/ledger.ts` (ใหม่): บันทึกรายวัน หนึ่งบรรทัดต่อวันใน `state/audit/ledger.jsonl`: จำนวน prompt, ถูกแก้, ตามงาน, ถามแล้วได้ "ทำ", การตัดสินแทน, คำถามที่มีคำแนะนำ, ผลของ run ที่เริ่มวันนั้น, model และเวอร์ชัน Claude Code ที่ใช้
  - รวมของเก่ากับของที่อ่านใหม่: วันไหนอ่านใหม่ได้ครบกว่าหรือเท่าเดิม ใช้ของใหม่ทั้งวัน ถ้าประวัติของวันนั้นถูกลบไปบางส่วน เก็บของเก่า
  - run ลงวันที่จาก id ของ run ไม่ใช่เวลาไฟล์ (run ที่ย้ายมาจาก engine เก่ามีเวลาไฟล์เป็นวันย้ายทั้งหมด)
  - ข้อความที่เก็บผ่าน `redact`
- `lib/backup.ts`: เพิ่ม `state/audit/ledger.jsonl` ใน backup เพราะสร้างใหม่ไม่ได้
- `collectors/audit.ts`: ยอด "ทั้งหมด" และรายการใน `decisions.md` มาจากบันทึกรายวัน · เตือนใน brief เมื่อมี turn ของ worker แต่อ่าน prompt ไม่ได้เลย หรือมี turn ต่อแต่ไม่พบคำสั่งเลย

## Phase 2: คำตัดสินหลังการเปลี่ยนแปลง

สถานะ: เสร็จ 12 พ.ย. 2026 · รอบ improve 29 และ 30 ต.ค. ได้คำตัดสิน "แยกไม่ออก" ทั้งคู่ (76% → 72% และ 75% → 76%)

ปัญหา: หลัง improve ไม่มีอะไรบอกว่าได้ผลไหม และบรรทัดเทียบก่อนหลังเดิมใช้ช่วงชั่วโมงที่ยืดไปเรื่อยๆ จนเลยช่วงที่มีข้อมูล (ตัวเลข 88% ก่อน improve 30 ต.ค. มาจาก run ที่ย้ายมาราว 200 งานซึ่งเวลาไฟล์ตรงกับวันย้าย)

- จุดเปลี่ยนมี 2 ชนิด: รอบ `improve:` (จาก git) และวันที่ model หลักเปลี่ยน (จากบันทึกรายวัน)
- แต่ละจุดเทียบ 7 วันก่อนกับ 7 วันหลัง: งานที่ส่งแล้วไม่ต้องแตะอีก และจำนวนถูกแก้ต่อ 100 prompt
- คำตัดสิน: ดีขึ้น, แย่ลง, แยกไม่ออก, ข้อมูลน้อย, ยังเร็วไป · "แย่ลง" ขึ้น brief พร้อมรายการ commit ของรอบนั้น
- เวอร์ชัน Claude Code เก็บไว้ในบันทึกรายวันแต่ไม่แสดง: Desktop กับ CLI ใช้คนละเวอร์ชันและสลับกันทุกวัน จึงบอก "ตั้งแต่วันไหน" ไม่ได้
- run ของชุดทดสอบ (repo อยู่ในโฟลเดอร์ชั่วคราวของเครื่อง) ไม่นับเป็นงานของเจ้าของ: run แบบนี้ 103 งานในช่วง 26 ถึง 28 ต.ค. ทำให้ตัวเลขก่อน improve สูงเกินจริง
- แทนบรรทัด "หลัง improve" เดิมและรายการ `audit:round`

## Phase 3: วัดคุณภาพงาน ไม่ใช่แค่ไม่ถูกแตะ

- run ที่ปิดแบบทิ้งงาน ไม่นับว่า "ไม่ต้องแตะ"
- แยก turn ที่เจ้าของแตะเป็น แก้ของผิด กับ เพิ่มโจทย์ (จากคำในข้อความที่ส่งต่อ)
- สัดส่วน run ที่เป็นงานของ twin เอง เทียบกับงานจริงในโปรเจกต์อื่น
- หมวดที่ twin ตัดสินแทนแล้วถูกสั่งแก้ซ้ำ ขึ้น brief ให้พิจารณาลดระดับ

## Phase 4: กฎไม่ทับถม

- `lib/identity.ts`: กฎมีวันที่ยืนยันล่าสุด · audit แสดงขนาด mode เทียบเพดาน และกฎที่ไม่มีหลักฐานใหม่เกิน 60 วัน
- `improve` skill: mode เกิน 80% ของเพดาน เพิ่มกฎได้เมื่อรวมหรือลบกฎเก่า · กฎที่ใช้กับโปรเจกต์เดียวไปอยู่ใน CLAUDE.md ของโปรเจกต์นั้นผ่าน `dispatch` · กฎที่มีไว้แก้นิสัยของ model ติดป้าย และทดสอบซ้ำเมื่อ Phase 2 แจ้งว่า model เปลี่ยน
- รัน `improve` จริงหนึ่งรอบกับ profile ของเจ้าของ และเติม `profile/coverage.md` จากประวัติที่เจ้าของยินยอมแล้ว

## ไม่ทำ และเหตุผล

- บังคับรูปแบบคำทาย ("ผมจะเลือก: X") ในทุกคำถาม: เพิ่มข้อความในทุกคำตอบ ขณะที่หมวดที่ยังต้องถามเหลือแต่เรื่องที่เจ้าของอยากให้ถามเสมอ (งานลูกค้า ของเสียเงิน การลบ) จึงไม่มีอะไรให้เลื่อนระดับเพิ่ม
- worker บน cloud ตอนปิดเครื่อง: โค้ดลูกค้าจะออกนอกเครื่อง
- รายการคำภาษาอื่น: skill และ brief ของ engine เป็นภาษาไทยทั้งชุด เจ้าของภาษาอื่นยังใช้ไม่ได้ตั้งแต่ก่อนถึง audit
- นับคำสั่งจากแถบ Desktop แยก: มันมาถึงเป็นข้อความของเจ้าของอยู่แล้ว จึงนับเป็นของเจ้าของถูกต้อง
- ให้ worker ถามกลางงาน: เป็นข้อแลกที่ design รับไว้แล้ว
